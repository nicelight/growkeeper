# GrowKeeper: правила разработки

- KISS. Проверить, нет ли функции уже. Чёткие входные/выходные контракты, минимум сценарных правил; сохранять владение, целостность, защиту от гонок и явное согласие на удаление.
- SDD в коде — только короткой шапкой: назначение, контракт, существенные ограничения. Без перечней проверяемого поведения.
- Остальные спецификации — в `docs/specs/`: **как работает и почему так**, без пересказа кода. Обновлять вместе с поведением.
- Минорные правки выполнять самостоятельно. При блокере, более трёх безуспешных попытках или необходимости мажорного изменения — остановиться и уведомить владельца.
- Work/Codex и задачи с расходом оплачиваемого инференса или лимитов — только с отдельным разрешением.
- Проверить тестами → опубликовать в GitHub → деплой на Cloudflare → проверить результат. Непройденные проверки обозначать явно.
- Секреты не помещать в репозиторий и логи; проверять перед публикацией.
- Пользовательские данные не перестраивать без согласования. Gardening сохраняет исходную историю.
- Общаться сжато: результат, проблема, следующий шаг.
